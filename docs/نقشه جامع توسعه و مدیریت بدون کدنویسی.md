# نقشه جامع توسعه و مدیریت بدون کدنویسی My-AI

> این فایل نتیجه audit مستقل پروژه است و از این به بعد مرجع اصلی برای تبدیل قابلیت‌های hard-coded به قابلیت‌های قابل مدیریت از طریق Settings/UI است.
>
> قانون: `[x]` فقط وقتی مجاز است که implementation + UI/API + persistence + validation + test + regression + verification کامل شده باشد. صرفاً وجود کد یا یک setting کافی نیست.

- [ ] تغییرات configuration audit شوند.
- [ ] امکان reset هر setting به default وجود داشته باشد.
- [ ] امکان export/import تنظیمات وجود داشته باشد.

## معیار نهایی پروژه

پروژه زمانی از نظر این نقشه «تکمیل‌شده» محسوب می‌شود که برای یک کاربر عادی، برای تغییر هر رفتار قابل تغییرِ سیستم، مسیر زیر وجود داشته باشد:

`Settings → انتخاب قابلیت → ایجاد/ویرایش → اعتبارسنجی → ذخیره → اعمال → تست → مشاهده نتیجه`

و برای قابلیت‌های حساس:

`Settings → تغییر → Approval → Snapshot → Apply → Health Check → Rollback در صورت خطا`

### اصل غیرقابل‌مذاکره

**اگر برای اضافه‌کردن یک LLM، provider، ابزار، منبع آموزشی، policy، workflow، integration یا رفتار قابل تنظیم مجبور شویم source code را ویرایش کنیم، audit باید آن مورد را به‌عنوان gap ثبت کند؛ مگر اینکه آن مورد ذاتاً یک قابلیت immutable و معماری‌محور باشد.**
