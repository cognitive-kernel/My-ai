# Testing Policy

برای هر بخش اصلی نقشه توسعه یک فایل تست مستقل در `tests/` ایجاد می‌شود.

- هر فایل تست حداکثر ۳۰ ثانیه مجاز به اجرا است.
- اگر اجرای یک فایل از ۳۰ ثانیه عبور کند، همان تست متوقف می‌شود.
- پس از timeout یا failure، علت خطا بررسی و ایراد مربوطه برطرف می‌شود.
- همان فایل پس از اصلاح دوباره اجرا می‌شود.
- این چرخه برای تمام فایل‌های تست ادامه پیدا می‌کند تا فقط تست‌های تأییدشده باقی بمانند.
- تست‌های E2E، regression، security و runtime نیز طبق همین چرخه اجرا و بررسی می‌شوند.
- هیچ گزینه‌ای در نقشه توسعه صرفاً به‌دلیل وجود کد `[x]` نمی‌شود؛ تأیید نهایی پس از تست و verification انجام می‌شود.
